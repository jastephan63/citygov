# quellen/ — sources, corrections and build inputs

This folder holds the evidence the databank rests on and the few files the
build reads besides `citygov.db`. Nothing here is written by `./build.sh`:
two loaders write evidence here — `scripts/register_katalog.py --abrufen`
the snapshots under `register/`, `scripts/load_gesetz_titel.py --lesen`
the law-title file —, `ch-geo.js` was compiled once from third-party data
(see below), and everything else is a reviewed file kept as it is; every
file is read by the script named beside it. Five files are inputs of
every `./build.sh` and must not move or be renamed: `verlauf_bemerkungen.json`,
`wortwahl_datum.json`, `ch-geo.js`, `konzepte.json` and
`parteien_stichprobe_2026-10-05.json`; so is the folder `register/`, whose
snapshots the gate of `scripts/validate_db.py` reads on every run. The correction files are named in the
scripts or in the `scripts/README.md` commands that apply them, so they keep
their names too (the naming corrections are picked by their keys).

Two reviewed decision files are read when they exist and are absent today:
`kennung_abloesungen.json` (`[{"alt", "neu", "grund"}]`, read by
`scripts/kennungen.py`: the only way a permanent identifier is ever marked
«abgelöst durch» another — never guessed) and `exportvertrag_hinweise.json`
(`[{"id", "export", "stufe", "text"}]`, read by `scripts/export_vertrag.py`
during the export: a key that kept its name but changed its meaning, which the
structure cannot show; applied once per id).

A new correction belongs here only with its reason inside the file (a
`hinweis` and, per entry, the evidence) and with the script that applies it
staging → validate → swap. A naming correction is picked up by
`run_begriffe.py` through its keys, not its name.
